# Unino — Sheet Music Platform

## What it is
Unino is a web platform for one-on-one online music lessons. The teacher (host) and student open the same
PDF score through a shared link and annotate it together in real time.

## Stack and layout
- `frontend/`: Next.js 16 (App Router, TypeScript, Tailwind), PDF.js (`pdfjs-dist`), pdf-lib,
  socket.io-client, Supabase Auth (`lib/supabase.ts`, env `NEXT_PUBLIC_SUPABASE_URL` / `_ANON_KEY` in `.env.local`).
  See `frontend/AGENTS.md`: this Next.js version has breaking changes, so read `node_modules/next/dist/docs/` first.
- `backend/`: Node/Express + Socket.IO, all in `backend/index.js` (port 3001, hardcoded). IMSLP logic in `backend/imslp.js`.
- Data: rooms are saved in `backend/data/rooms.json`. Uploaded PDFs go in `backend/uploads/` (gitignored).
- Key frontend files (`frontend/app/`): `page.tsx` (main page, socket wiring), `PDFViewer.tsx` (rendering + annotation),
  `Toolbar.tsx`, `exportAnnotatedPDF.ts` + `ExportModal.tsx`, `LayersPopover.tsx`, `ChatPanel.tsx`,
  `RaisedHandsPanel.tsx`, `TunerPanel.tsx` (+ `hooks/usePitch.ts`, `lib/pitch.ts`, `PitchTrace.tsx`),
  `MetronomePanel.tsx`, `ThumbnailPanel.tsx`, `Sidebar.tsx`, `IMSLPPanel.tsx`, `NicknameModal.tsx`,
  `AuthModal.tsx`, `AccountPanel.tsx`, `lib/sessions.ts`.
- Symbols: `frontend/app/symbols.ts` is generated by `scripts/extract-glyphs.cjs` (Bravura / STIX Two, OFL licenses
  in `frontend/public/licenses/`). Do not edit it by hand. (A second copy of the script exists in `frontend/scripts/`.)
- OMR: `scripts/omr-test/run_omr.sh` + `INSTALL.md` (Audiveris → MusicXML + measure bounding boxes).
- `supabase_migration_recent_sessions.sql` at the root (recent sessions table).

## Deploy
See `DEPLOY.md` (Vercel frontend + Railway backend with a volume). Settings: `NEXT_PUBLIC_BACKEND_URL` (frontend);
`PORT`, `FRONTEND_ORIGIN`, `DATA_DIR`, `ENABLE_OMR` (backend). PDFs are stored as `/uploads/<file>.pdf` (path only).

## Run locally
Backend (terminal 1):
    cd ~/sheet-music-platform/backend && node index.js     # http://localhost:3001
Frontend (terminal 2):
    cd ~/sheet-music-platform/frontend && npm run dev      # http://localhost:3000
(The backend has no npm start script. There are no tests.)

## Conventions
- Annotation coordinates are normalized from 0 to 1 relative to the page (e.g. `MIN_DIM = 0.005` in PDFViewer).
- Host identity is a stable token (`hostToken`, stored hashed as `hostTokenHash` in rooms.json), not the socket id.
  Logged-in Supabase users can also be recognized as the host.
- Permissions are checked on the server: only the host or the shape's owner can update or delete a shape.
- Everything in the app UI and in code comments must be in English.

## Working rules (the user is a beginner)
- Give short, copy-pasteable steps.
- After each change, say exactly how to verify it.
- Report honestly what was actually run and tested versus only changed in code.
- Ask before anything that needs sudo or a password, and before installing from an unofficial source.
- Do not push to GitHub unless asked (repo is on `main`, tracking `origin/main`).

## Known state
- Symbol library v5 (approved 2026-11-10, uncommitted): 37 symbols in `frontend/app/symbols.ts`
  (preview: `scripts/symbol-library-v5-preview.html`). The extract-glyphs scripts are outdated and the font files
  are not in the repo; v5 additions were generated with Bravura from Steinberg's GitHub. No erhu string marks (user declined).
  In the app: `SymbolPalette.tsx`, annotation type `symbol` {symbolId, x, y, w, h, color}; Symbols tool, right-click /
  long-press menu, keys 0–4 = fingering, S/M/L size scaled from OMR staff height when known.
- IMSLP search/import exists (`GET /imslp/search`, `POST /imslp/import`).
- OMR is integrated (2026-11-10, uncommitted): `backend/omr.js` runs `~/audiveris/Audiveris.app` (bundled Java) and
  reads measure boxes from the .omr file; results are cached in `backend/data/omr/<pdf-stem>/` (measures.json, score.mxl).
  The host starts it from the "Measures" panel (`OMRPanel.tsx`). It is slow: ~1.5–2 min per page.
  Optional per-viewer toggles: bar numbers, shared bar highlight, click-to-highlight, jump to bar (host jump syncs), MusicXML export.

## Features today (from the code)
- Rooms and share links (`/create-room`, `/upload`, `/room/:roomId`, socket `join-room`)
- Annotation tools, plus undo, clear and a laser pointer
- Move/resize of annotations (drag handles)
- Layers per person
- Nicknames (`rename`)
- Raise hand (raise, lower, dismiss)
- Chat
- Tuner with shared pitch updates
- Shared metronome
- Bookmarks, page thumbnails, page and scroll sync
- Export annotated PDF (pdf-lib)
- Accounts (Supabase Auth) and recent sessions
- Measures (OMR): bar numbers, highlight, jump to bar, MusicXML export
- Music symbols: Symbols tool, right-click / long-press palette, fingering keys 0–4
- Undo/redo history in groups (one eraser swipe = one step); Cmd/Ctrl+Z, Shift+Cmd/Ctrl+Z, Ctrl+Y
- "Follow teacher" chip for students: follows page, bar jumps and (if the teacher shares it) scroll;
  hand-scrolling or changing page pauses it; one click jumps back to the teacher
- Server saves rooms.json coalesced + atomically (temp file + rename) — overlapping writes used to corrupt it
